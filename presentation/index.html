Why it
must change

The design fits the farm it was written for. Run 4 is not that farm, and the machine is only off once.

LHC switched off 29 June 2026
Run 4 first beam June 2030

  • Not scalable One server and one SQL table for the whole farm. You can add nodes; there is nothing to add at the other end.
  • Not durable Past 500 messages a second a process writes to a file in /tmp, then drops. It recovers only below 10 a minute, so the record thins exactly during an incident.
  • Not searchable Message bodies sit in an unindexed text column, and archiving renames the table. Free-text search is a scan, across tables chosen by hand.
  • Not complete Only what is injected through the API arrives. DDS task logs and process stdout stay on node disks.
  • Not extensible One script bridging to a syslog socket is the way out. No bus, and nowhere to attach detection or alerting.
